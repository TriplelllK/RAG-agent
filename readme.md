# RAG-agent У-300 КТЛ-1

RAG-агент для технической документации установки У-300 КТЛ-1
(регламент, нормы технологического режима, аварии и сигнализации).

Что делает:
- ищет фрагменты в документах по векторному индексу + rerank;
- подтягивает структурные данные по приборам (нормы, уставки, действия);
- формирует ответ через LLM с цитатами на документ и страницу.

## Документы

В реальной работе используются три типа документов установки:
1. Технологический регламент.
2. Нормы технологического режима.
3. Аварии и сигнализации.

В репозитории — публичный демо-корпус в `sample_data/` (фиктивные данные,
структура соответствует реальным документам).

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Опционально для LLM-режима:

```powershell
$env:OPENAI_API_KEY = "your_api_key"
$env:OPENAI_MODEL   = "gpt-4o-mini"
```

## Запуск

```bash
python ingest.py --data_dir sample_data --out_dir storage --force
streamlit run app.py
```

Без LLM ключа интерфейс всё равно работает на retrieval-only.

## Структура

- `app.py` — Streamlit-интерфейс
- `ingest.py` — нарезка документов и сборка FAISS-индекса
- `rag_core.py` — поиск, rerank, генерация ответа
- `rag_structured.py` — нормы и аварии (поиск по прибору/оборудованию)
- `parsers/` — парсеры таблиц из PDF (нормы, аварии)
- `eval/` — оценка качества и графики метрик

## Оценка качества

```bash
python eval/eval_rag.py --gold eval/gold_qa_sample.jsonl --k 4 --no-llm
```

Метрики:
- `Recall@k` — попал ли нужный документ в top-k
- `MRR@k` — позиция нужного документа
- `Faithfulness (proxy)` — есть ли в цитатах ключевые слова из эталона
- `Answer with citation rate` — есть ли цитаты в ответе
- `Instrument hit rate` — нашли ли прибор в структурных нормах/авариях

Результаты на публичном sample-наборе (N=12, k=4, без LLM):

| Метрика | Значение |
| --- | ---: |
| Recall@4 | 1.00 |
| MRR@4 | 0.85 |
| Faithfulness (proxy) | 1.00 |
| Citation rate | 1.00 |
| Instrument hit rate | 0.00 |

Несколько замечаний по цифрам:
- Recall и citation rate насыщены потому, что корпус из 3 документов и 13
  фрагментов — задача поиска тут лёгкая.
- MRR < 1.0 значит, что для пары вопросов нужный документ оказался не на
  первой позиции (а на 2-3).
- Instrument hit rate = 0 ожидаемо: в sample-данных нет реальных тегов
  приборов (типа `LIC-31050`), а структурные таблицы `storage/norms.json`
  и `storage/alarms.json` — с других, закрытых документов.

Сохранение истории метрик и графики:

```bash
python eval/track_metrics.py render
```

## Примеры вопросов

- «Какие уставки LIC-31050 и PDT-31016?» — нормы по приборам
- «Какие автоматические действия при падении расхода амина FT-310452?» — аварии
- «Что является продуктами установки 300?» — текстовый вопрос по регламенту
- «Какие сигнализации есть для F-301?» — по оборудованию

Что входит в «хороший» ответ:
1. Конкретные теги приборов/оборудования из вопроса.
2. Числовые значения и единицы, если речь про уставки.
3. Действия при срабатывании, если речь про аварию.
4. Цитаты на документ и страницу.
5. Нет фактов, которых нет в документах.

## Замечания

- Эмбеддинг-модель по умолчанию `paraphrase-multilingual-MiniLM-L12-v2`,
  переопределяется через `EMB_MODEL`.
- Если нет `storage/faiss.index`, сначала запустите `ingest.py`.
